# HomeMusic для Windows

Версия **1.2.0**: адаптивная настольная навигация, заметные состояния наведения, улучшенная доступность
и плоский список треков в библиотеке. Для нового интерфейса обновите Хаб вместе с веб-сборкой.

Настольный клиент на Electron открывает интерфейс вашего Хаба. В превью окна на панели задач
доступны **предыдущий трек**, **воспроизведение / пауза**, **следующий трек** — в том числе
при свёрнутом окне. Используется тот же веб-плеер, его очередь, перемешивание и повтор.

## Установка и подключение

1. Обновите Хаб вместе с веб-интерфейсом: из корня репозитория `docker compose up -d --build hub`.
   Кнопкам нужен мост плеера из актуального `web/src/lib/desktopPlayer.ts`.
2. В веб-интерфейсе откройте **Ещё → Приложение для Windows** или адрес Хаба `/desktop/latest.exe`.
    Запустите полученный установщик. Локальный установщик версии 1.2.0: `desktop/dist/HomeMusic-Setup-1.2.0.exe`.
3. Откройте **HomeMusic** из меню «Пуск» и укажите адрес Хаба, например `https://music.example.ru`
   или `http://localhost:8080`. Указывается корневой адрес, без `/api` и других путей.
4. Войдите в свой аккаунт, включите музыку и наведите курсор на значок HomeMusic на панели задач.
   Центральная кнопка переключается между воспроизведением и паузой. В конце очереди кнопка
   следующего трека отключается; при повторе всей очереди доступен переход к её началу.

Кнопка предыдущего трека работает как в интерфейсе: после трёх секунд возвращает к началу
текущего трека, в начале — к предыдущему. Без выбранного трека все три кнопки неактивны.
При загрузке доступна пауза, при ошибке кнопка воспроизведения повторяет запуск.

Адрес Хаба меняется через **Alt → HomeMusic → Адрес Хаба…**. Перезагрузка — **Ctrl+R**.
Повторный запуск программы открывает уже существующее окно. Сворачивание сохраняет воспроизведение;
закрытие окна завершает клиент. При недоступности сервера открывается окно повторного подключения.

Адрес сохраняется в `%APPDATA%/homemusic-desktop/config.json`, авторизация и очередь — в профиле
Electron рядом с ним. Вход из Chrome автоматически не переносится. Интерфейс загружается с Хаба,
поэтому его обновления применяются без переустановки настольного клиента.

## Обновления через Хаб

Начиная с **1.0.2**, клиент сам проверяет выбранный Хаб через 10 секунд после подключения
и затем каждые 6 часов. Новая версия скачивается в фоне; SHA-512 проверяет electron-updater.
Прогресс виден в меню **Alt → HomeMusic**. После загрузки появляется уведомление и пункт
**Перезапустить и обновить до …**. Обновление устанавливается без мастера при закрытии приложения
или сразу по этому пункту с последующим запуском. Во время прослушивания самопроизвольного перезапуска нет.
При ошибке сети или проверки файла приложение продолжает работать; проверку можно повторить через меню.

Версии 1.0.0/1.0.1 не содержат обновлятор: для них требуется один раз установить 1.0.2
с `/desktop/latest.exe` поверх текущей версии. Аккаунт и настройки сохраняются.
Дальнейшая передача установщиков пользователям не нужна.

Обновления загружаются с того же Хаба, который выбран при подключении:
`/desktop/updates/windows/x64/latest.yml`. При смене сервера незавершённая загрузка отменяется,
а скачанное обновление прежнего сервера не устанавливается. Адрес публикации в конфигурации сборщика
заменяется адресом выбранного Хаба при запуске; URL продакшена в EXE не зашит.

### Публикация следующей версии

1. Увеличьте `version` в `desktop/package.json`, обновите `package-lock.json` командой `npm install`
   и выполните `npm run dist:win`. Собирайте полный NSIS target: он создаёт также `app-update.yml`,
   `latest.yml` и `.exe.blockmap`, необходимые обновлятору.
2. Перенесите три файла из `desktop/dist/` на сервер: `latest.yml`, `HomeMusic-Setup-X.Y.Z.exe`
   и `HomeMusic-Setup-X.Y.Z.exe.blockmap`.
3. Из каталога развёртывания Compose скопируйте их в промежуточный каталог постоянного тома и опубликуйте:

   ```sh
   homemusic-compose exec -T hub mkdir -p /data/windows-release-staging
   homemusic-compose cp release/. hub:/data/windows-release-staging/
   homemusic-compose exec -T hub python scripts/publish_windows_release.py /data/windows-release-staging /data/windows-releases
   curl -fsS http://127.0.0.1:8080/desktop/updates/windows/x64/latest.yml
   ```

   Для обычного Compose замените `homemusic-compose` на `docker compose`. `release/` — каталог
   с тремя файлами. `WINDOWS_RELEASES_DIR` позволяет выбрать другой каталог; по умолчанию используется
   `/data/windows-releases`, сохраняющийся при пересборке и пересоздании контейнера.

Скрипт сначала проверяет SHA-512 и размер установщика, публикует неизменяемые артефакты и последним
атомарно заменяет манифест. Повторная публикация тех же файлов допустима, перезапись другим содержимым
и публикация меньшей версии запрещены. Сохраняйте прежние `.exe` и `.blockmap` для дифференциальных загрузок.
Для публикации очередного EXE пересобирать и перезапускать Хаб не требуется.

## Разработка и сборка

Windows 10/11 x64, Node.js 24 LTS и npm. Для запуска и проверки используйте репозиторий на локальном
диске Windows (например, `C:\work\HomeMusic`): запуск Electron с UNC-пути WSL/сетевого диска
может блокировать дочерние процессы Chromium. Сервер Хаба может работать в WSL или на другом компьютере.

Из `desktop/`:

```powershell
npm ci
npm start
```

В окне подключения можно указать `http://localhost:5173`, если веб-интерфейс запущен через
`npm run dev` или `npm run dev:mock` из `web/`.

```powershell
npm test
npm run test:e2e
npm run dist:win
```

Установщик: `desktop/dist/HomeMusic-Setup-1.2.0.exe`. Распакованный клиент для проверки:
`desktop/dist/win-unpacked/HomeMusic.exe`. Сборка создаёт ярлыки на рабочем столе и в меню «Пуск».
Для подписи опубликованных сборок electron-builder поддерживает `CSC_LINK` / `CSC_KEY_PASSWORD`.

Проверка уже собранного клиента:

```powershell
$env:HOMEMUSIC_TEST_EXECUTABLE = 'C:\build\HomeMusic\HomeMusic.exe'
npm run test:e2e
```

E2E запускает настоящий Electron с отдельным временным профилем и локальным тестовым Хабом,
проверяет нативный вызов создания кнопок, команды при свёрнутом окне, сохранение адреса,
сброс при перезагрузке и изоляцию моста от посторонних страниц.
Для собранного клиента также проверяет скачивание обновления настоящим electron-updater
и отказ при несовпадении SHA-512; тестовые установщики не запускаются.
Связь с реальным веб-плеером проверяется из `web/`:

```powershell
npm run build
npm run test:e2e -- tests/desktop-player.spec.mjs
```

После установки на Windows можно дополнительно проверить вид превью вручную: включить плейлист,
свернуть окно и нажать три кнопки в превью; проверить конец очереди, повтор и выход из аккаунта.

## Устройство клиента

### Если кнопки отсутствуют или неактивны

В версии 1.0.1 панель создаётся после показа окна независимо от состояния веб-плеера.
Откройте **Alt → HomeMusic → Диагностика плеера…**: там видны версия клиента,
идентификатор веб-сборки, результат создания панели Windows и наличие связи с плеером.
Если связи нет, убедитесь, что Хаб пересобирается именно из каталога с изменениями
`web/src/lib/desktopPlayer.ts` и `web/src/lib/listen.ts`, затем выполните в этом каталоге
`docker compose up -d --build hub` и нажмите **Ctrl+R** в Windows-клиенте.
Обновление только установщика не добавляет мост плеера в веб-сборку на сервере.

### Компоненты

- `src/main.cjs` — окно, профиль, подключение к Хабу и нативные `setThumbarButtons` Windows.
- `src/preload.cjs` — изолированный мост: состояние плеера наружу, три команды внутрь.
- `src/setup.*` — локальная русскоязычная форма адреса и повторного подключения.
- `src/updates.cjs` — фоновые обновления NSIS через выбранный Хаб, прогресс и установка при закрытии.
- `../web/src/lib/desktopPlayer.ts` — синхронизация кнопок с `listen.ts`; частые обновления позиции
  не создают лишних IPC-сообщений.

У удалённого интерфейса нет доступа к Node.js и произвольным IPC-каналам. Мост доступен только
главному фрейму выбранного Хаба. Ссылки на другие сайты открываются в обычном браузере.
